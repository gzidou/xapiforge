验证指南 ​

本文记录仓库当前可重复执行的验证入口。提交前直接运行 pnpm verify；定位问题时再按下面的层级单独运行。

对应场景清单见 scenarios.md（97 个场景）和行为契约 behavior-contract.md。

两层验证体系 ​

层级范围工具命令自动化
L1 库层HttpClient / AuthService / middleware / createNetNode + tsxpnpm test:scenarios✅ 全自动
L2 端到端demo-app 页面 + 浏览器 + mock-serverPlaywright 或人工pnpm test:demo-app半自动

改代码后回归顺序：L1 → （改了 demo-app 业务代码时）L2。

genapi v2 验证 ​

修改生成器、配置、fixture 或生成客户端模板时，先运行：

bash
pnpm --filter '@xapiforge/genapi' test
pnpm --filter '@xapiforge/example-demo-app' typecheck
cd examples/demo-app
pnpm download-swagger
pnpm run generate:api -- --check

genapi 测试覆盖配置校验、规范化文档复用、多服务 schema 隔离、分层运行时 URL、runtime enum/Flags、legacy hook、确定性 manifest、只读 check、事务恢复、stale 文件清理和独立 CLI 消费者。

--check 通过时输出 UNCHANGED；运行后不应出现 .xapiforge-lock、staging、backup 或事务状态残留。发布前还要执行根目录 pnpm publish:dry-run，检查真实 tarball。

L1：库层自动验证（首选，必跑） ​

脚本：scripts/test/scenarios.ts命令：

bash
pnpm test:scenarios

特性：

  • 自动起停 mock-server（已运行则复用，未运行则拉子进程，跑完自动 kill）
  • 直接 import @xapiforge/core，不依赖浏览器
  • 9 个 Section 共 222 个断言；场景与断言不是一一对应，一个场景可能包含多个检查
  • 覆盖：HttpClient HTTP 层 / middleware 单元 / AuthService 单飞+窗口 / C1-C10 envelope 变体 / 429 重试 / A14 业务 200 鉴权码 / A16+D2+D7 端到端鉴权 / B19 文件下载

加新断言 ​

在 scripts/test/scenarios.ts 对应 Section 加 { ... } 块，用 ok() / eq() / expectThrows() 断言。mock-server 端点不够时，在 scripts/mock-server.ts 的 handleTestEndpoint switch 加 case。

L2：浏览器端到端验证 ​

适用：改了 demo-app 业务代码（abp-unwrap-mw.ts / main.ts / 页面）后跑。

前置：

bash
# 终端 1：起 mock（保持运行）
pnpm mock

# 终端 2：起 demo-app dev server（保持运行）
pnpm --filter '@xapiforge/example-demo-app' dev
# 打开 http://localhost:5173

自动执行需要本机已经安装 Python Playwright 和 Chromium：

bash
python3 -m pip install playwright
python3 -m playwright install chromium
pnpm test:demo-app

test:demo-app 不负责启动 mock-server 和 Vite；两个服务都要保持运行。没有 Python Playwright 时，可以打开 /scenarios 后点击 Run All，按下表人工核对。

场景清单 ​

#场景操作期望

5A17 429 限流console: fetch("/api/test/429-with-retry-after", {headers:{Authorization:"Bearer mock-token"}})退避重试后抛错
6B19 文件下载console: fetch("/api/test/download").then(r=>r.blob()).then(b=>console.log(b.size))输出 1024
7C1-C10 envelope 变体console: fetch("/api/test/c1-data-string").then(r=>r.json())返回 {code:0, data:"https://file.url"}
8跨刷新 token 持久化登录后 F5 刷新页面仍在 /，列表重新加载（token 从 localStorage 恢复）

DevTools console 快捷脚本 ​

js
// 查看当前 token
console.log("access:", localStorage.app_token, "refresh:", localStorage.app_refresh_token);

// 模拟 token 过期（触发 A16）
localStorage.app_token = "expired";

// 模拟 refresh token 失效（触发 D2 跳登录）
localStorage.app_refresh_token = "invalid";
localStorage.app_token = "expired";

// 清空 token（相当于登出）
localStorage.removeItem("app_token");
localStorage.removeItem("app_refresh_token");

// 调用 api（main.ts DEV 模式已暴露 window.__api）
await window.__api.base.GET("/api/identity/users");

CI 集成 ​

.github/workflows/ci.yml 在 pull request 和 main 推送时运行 lint、format、build、test 和 docs 五类 job。test job 包含包测试、test:scenarios 和 test:download；浏览器测试依赖额外的 Playwright 环境，目前仍由维护者在涉及 demo 改动时执行。

提交前验证清单 ​

bash
pnpm verify

涉及 demo 页面时，再启动 mock 和 demo 后运行：

bash
pnpm test:demo-app

常见问题 ​

Q: pnpm test:scenarios 报端口占用？ A: 脚本会先探测 8787 是否可用；已运行的 mock 会复用。若 pidfile 残留但进程已死，删 /tmp/demo-mock.pid 重试。

Q: 改了库代码后 L1 通过但 L2 失败？ A: L2 走真实浏览器 + demo-app，可能是 demo-app 业务侧代码（如 abp-unwrap-mw.ts）的问题，不是库的问题。看浏览器 DevTools 的 Network / Console 定位。

Q: 加了新场景怎么补测试？ A:

  1. 库层场景 → 在 scripts/test/scenarios.ts 加断言
  2. mock 端点不够 → 在 scripts/mock-server.ts 的 handleTestEndpoint 加 case
  3. 端到端场景 → 在 VALIDATION.md 的 L2 场景清单加一行
  4. 更新 docs/internals/scenarios.md 和 docs/internals/behavior-contract.md 的覆盖表
